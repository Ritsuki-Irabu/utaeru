# Issue #18 お気に入り・プレイリストUX設計

## 1. 用語と役割

### お気に入り

曲検索画面などからユーザーが追加した、すべての曲を集める個人用ライブラリです。従来の内部名称 `my_songs` とAPIパス `/my-songs` は既存データと互換性を保つため維持しますが、ユーザー向け画面では「お気に入り」と表示します。

- 追加した全曲を一覧表示する
- メモ・タグを曲ごとに編集できる
- 曲をお気に入りから解除できる
- CSVへ出力できる
- 一覧では再生せず、曲情報カード全体のボタンから曲詳細へ移動する

### プレイリスト

お気に入りの曲を、用途・練習順・イベントなどで複数のグループに分けるためのリストです。1ユーザーが複数作成でき、名前・説明・曲順・曲メモを管理できます。

- お気に入りとは独立して複数作成できる
- 曲を追加・並び替え・削除できる
- 共有リンクを発行し、読み取り専用で共有できる
- プレイリスト詳細画面で曲を確認し、曲詳細画面で再生する

## 2. 再生導線

一覧画面や検索結果カードには音声プレイヤー・リズムプレイヤーを置きません。誤操作を減らし、曲のメタデータと再生操作を分離するためです。

1. お気に入り・検索結果で曲を確認する
2. 曲情報カードを押す
3. `/songs/{id}` の曲詳細画面でBPMリズムとYouTube MV再生を操作する

プレイリストの曲一覧から曲を選択すると曲詳細画面へ遷移します。共有プレイリストも同じ導線を使います。画面の責務分離は[Issue #19設計書](08_playlist_navigation_ux_design.md)で具体化します。

## 3. 表示ルール

- お気に入り追加操作はハートアイコン（未追加 `♡`、追加済み `♥`）で表示し、`aria-label` と `title` で意味を補足する
- 外部検索結果のラベルは「検索サービスの候補」とし、「外部カタログ」という専門用語を使わない
- プレイリスト選択の未選択状態は、画面にかかわらず「プレイリストを選択」に統一する
- 基本テーマはダークモードとし、暗い背景・明るい文字・十分なコントラストを標準にする

## 4. API・実装方針

- 既存の `/my-songs` API、`MySong`モデル、Policyは変更せず互換性を保つ
- `GET /api/songs/{song}` を追加し、曲詳細画面のResourceレスポンスを返す
- フロントエンドの表示名・導線のみを「お気に入り」に整理する
- 再生コンポーネントは曲詳細に限定して配置する
