# Playwright画面テストケース

## 目的

画面遷移、認証ガード、主要なユーザー操作を自動確認し、テスト中に見つかった不具合・UX課題を改修フェーズへ引き継ぐ。

## 実行方法

初回のみ、PlaywrightのChromiumをインストールする。

```bash
./vendor/bin/sail npm --prefix frontend exec playwright install chromium
```

その後、開発サーバーを自動起動してテストを実行する。

```bash
./vendor/bin/sail npm --prefix frontend run test:e2e
```

ブラウザを表示して操作を確認する場合：

```bash
./vendor/bin/sail npm --prefix frontend run test:e2e:headed
```

エディターのポートフォワーディング経由でテスト画面・実行状況を確認する場合：

```bash
./vendor/bin/sail npm --prefix frontend run test:e2e:ui
```

表示された `http://localhost:9323` をエディターのブラウザで開く。

UIでテストを選択して `Run` を押すと、実行後にテスト詳細から動画とTraceを開ける。実際のVue画面を直接確認する場合は `http://localhost:5173` を開く。

VS Code拡張で実行中のブラウザを表示する場合は、PlaywrightサイドバーでChromiumを有効にし、`Show Browsers`をONにしてからテストを実行する。UIモードのURLを開くだけでは、実ブラウザウィンドウは表示されない。

## 実行結果

2026-07-20のSail環境でChromiumを使い、15ケースすべて成功した。

全ケースでスクリーンショット（15件）と動画（15件）を `frontend/test-results/` に保存している。設定上、スクリーンショットは成功・失敗にかかわらず必ず取得する。

初回実行ではAPIモックのURLパターンがViteのモジュールURLまで捕捉する問題が発生したため、APIホストを`localhost`に限定している。これはテスト基盤の不具合であり、アプリ本体の不具合ではない。

## 静的レビューで見つかった確認候補

ブラウザ実行で再現性を確認するまでは、以下は「確定した不具合」ではなく、UX課題の候補として扱う。

- 未定義URLに対するNot Found画面がない

## 課題記録ルール

Playwrightが失敗した場合は、次の情報をIssueへ記録する。

- ケースIDと再現手順
- 期待結果と実際の結果
- `bug` / `ux` / `accessibility` / `security` / `performance` の分類
- P0〜P3の優先度
- 影響する画面・API・データ
- スクリーンショットまたはTrace

テストコードは期待される仕様を表すため、仕様変更でない限り失敗したテストを削除せず、修正後も回帰テストとして残す。
