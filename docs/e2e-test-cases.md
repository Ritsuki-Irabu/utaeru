# Playwright画面テストケース

## 目的

画面遷移、認証ガード、主要なユーザー操作を自動確認し、テスト中に見つかった不具合・UX課題を改修フェーズへ引き継ぐ。

## 実行方法

初回のみ、PlaywrightのChromiumをインストールする。

```bash
./vendor/bin/sail npm --prefix frontend exec playwright install chromium
```

その後、開発サーバーを自動起動してテストを実行する。

```bash
./vendor/bin/sail npm --prefix frontend run test:e2e
```

デスクトップChromeに加えて、ChromiumでiPhone相当の390×844・タッチ操作を再現する`mobile`プロジェクトも実行される。

起動中のLaravel APIへ接続して、ログイン・曲取得・お気に入り更新・プレイリストCRUD・共有発行/無効化を確認する場合は、次を実行する。検証用に作成したお気に入り・プレイリストは終了時に復元または削除される。

```bash
./vendor/bin/sail npm --prefix frontend run test:live-api
```

接続先や認証情報を変更する場合は、`E2E_API_URL`、`E2E_SMOKE_EMAIL`、`E2E_SMOKE_PASSWORD`を環境変数で指定する。

ブラウザを表示して操作を確認する場合：

```bash
./vendor/bin/sail npm --prefix frontend run test:e2e:headed
```

エディターのポートフォワーディング経由でテスト画面・実行状況を確認する場合：

```bash
./vendor/bin/sail npm --prefix frontend run test:e2e:ui
```

表示された `http://localhost:9323` をエディターのブラウザで開く。

UIでテストを選択して `Run` を押すと、実行後にテスト詳細から動画とTraceを開ける。実際のVue画面を直接確認する場合は `http://localhost:5173` を開く。

VS Code拡張で実行中のブラウザを表示する場合は、PlaywrightサイドバーでChromiumを有効にし、`Show Browsers`をONにしてからテストを実行する。UIモードのURLを開くだけでは、実ブラウザウィンドウは表示されない。

## 実行結果

現行のテストコードには43ケースがあり、デスクトップとモバイル相当Chromiumの2プロジェクトで実行するため、通常は最大86テストとして実行される。モバイルはWebKitではなく、環境依存のブラウザ追加インストールを避けるためChromiumの端末エミュレーションで検証する。

全テストでスクリーンショットと動画を `frontend/test-results/` に保存している。設定上、スクリーンショットは成功・失敗にかかわらず必ず取得する。Issue #16〜#34の主要画面では、確認用スクリーンショットをテストコードから明示的に保存する。

初回実行ではAPIモックのURLパターンがViteのモジュールURLまで捕捉する問題が発生したため、APIホストを`localhost`に限定している。これはテスト基盤の不具合であり、アプリ本体の不具合ではない。

## 実API・外部障害の追加確認

- 実APIスモークで、Seederの一般ユーザーを使ったログイン、`/user`・曲一覧取得、お気に入り更新、プレイリストの作成・更新・曲追加/削除・共有発行/無効化・削除を確認する。
- iTunes検索・YouTube候補取得は実環境で成功を確認する。外部APIが失敗しても、ローカル曲検索は継続し、YouTubeは再試行可能なエラーを表示する。
- DeezerがBPMを返さない曲は`BPM未登録`として保存・表示を許容する。管理者は再取得または手動入力で補完できる。
- 曲詳細カテゴリのドラッグ中は挿入ラインを表示し、カード間・リスト末尾でもドロップできる。操作説明の重複文言は表示しない。
- 曲検索カードのプレイリスト登録は＋アイコンに集約し、プレイリストが1件の場合は1回の操作で追加できる。
- 曲検索・お気に入り・プレイリスト一覧では、歌詞の先頭行を「歌いだし」として表示し、未登録時は状態を明示する。
- 曲詳細の「リズムを確認する」「MVを再生する」「歌詞を表示する」は初期状態を閉じ、先頭アイコンと矢印付きの見出しから必要なカテゴリだけを開ける。3つの見出しは同じ高さ・文字サイズで表示される。
- 歌詞プレビューの歌いだしは、ラベル文字ではなく音符アイコン（アクセシブル名:「歌いだし」）で表示する。
- 詳細カテゴリを開くときは、内容が上方向から滑らかに展開される。
- MV埋め込みは`autoplay=0`で表示され、動画内のYouTube標準コントロールをユーザーが操作するまで自動再生しない。
- BPM未登録曲は外部APIの不確かな候補を採用せず、詳細のタップテンポで端末内に暫定値を保存できる。
- MV再生中は「別のMV」から現在候補を除外して次候補を選べる。
- お気に入り画面では曲名・アーティスト・メモ・タグを検索でき、CSV出力は右上のアイコンから実行できる。
- 曲検索から曲詳細へ遷移した場合、検索条件を保持したまま「曲検索へ戻る」で一覧へ復帰できる。
- 同一ユーザー・同一曲のお気に入り登録はAPIのバリデーションとDB一意制約で防止する。
- 検索画面はお気に入り一覧を読み込み、登録済み曲のハートを点灯状態で表示する。点灯中のハートを再タップすると削除APIを呼び出して解除する。
- お気に入り一覧の歌いだしが未取得の場合は、曲詳細と共通の歌詞APIを取得して表示する。取得した歌詞は曲マスタへ保存し、次回以降の一覧でも再利用する。
- YouTube動画の操作説明文は画面に表示せず、標準プレイヤーのUIだけを利用する。

## 課題記録ルール

Playwrightが失敗した場合は、次の情報をIssueへ記録する。

- ケースIDと再現手順
- 期待結果と実際の結果
- `bug` / `ux` / `accessibility` / `security` / `performance` の分類
- P0〜P3の優先度
- 影響する画面・API・データ
- スクリーンショットまたはTrace

テストコードは期待される仕様を表すため、仕様変更でない限り失敗したテストを削除せず、修正後も回帰テストとして残す。
