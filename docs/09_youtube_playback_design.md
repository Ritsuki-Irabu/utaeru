# Issue #20 YouTube MV再生設計

## 目的

曲詳細画面から「再生する」ボタンを押すと、曲に登録されたYouTube動画をウタエル内の公式YouTubeプレイヤーで表示する。動画は自動再生せず、再生開始は動画内の標準コントロールに任せる。

YouTube専用の検索窓は用意しない。内部の再生キャッシュがあればその動画を使い、未登録の場合だけ、MVボタン押下時にバックエンドが曲名・アーティスト名で検索する。ユーザー画面は再生に専念する。

## 利用フロー

1. お気に入りまたはプレイリストから曲詳細を開く。
2. 「再生する」ボタンを押す。
3. 内部の再生キャッシュがあればそれを使い、未登録なら内部APIで候補を取得する。
4. アプリ共通のMV再生ドックに公式YouTubeプレイヤーを表示する。
5. 動画と音声を標準プレイヤーで再生する。
6. 再生・一時停止・停止・シーク・音量変更は、表示されたYouTube動画内の標準コントロールから行う。

検索結果はYouTube Data APIの音楽カテゴリ（`videoCategoryId=10`）を対象にし、曲名・アーティスト名を引用符付きで検索する。再生画面からは曲ID（`song_id`）をAPIへ渡し、バックエンドが曲マスタからタイトル・アーティストを再構成するため、画面側の検索語と別曲が紐づくことを防ぐ。候補タイトルに対象曲名が含まれない場合は、別曲を返さず空結果にする。モバイルでも再生できるよう`videoEmbeddable=true`と`videoSyndicated=true`を指定し、音楽カテゴリで候補が空の場合だけカテゴリ指定を外して再検索する。`videoEmbeddable`だけに依存せず`videos` APIで現在の公開状態・処理済み状態・埋め込み可否を再検証する。候補タイトル・チャンネルの「Official Video」「MV」「VEVO」などを加点し、ライブ・カバー・演奏・歌ってみた等を大きく減点する。スコアが同点の場合も動画タイトルとIDを固定キーで比較するため、APIの返却順による揺れを抑える。削除済み・非公開・埋め込み不可の候補は表示しない。

再生中にYouTube側で利用不可になった場合は、エラー画面から次の候補または最新候補を再検索できる。再生中も「別のMV」から現在候補を除外して次候補へ切り替えられる。動画内の再生・一時停止・音量・シークは引き続きYouTube標準コントロールを使う。

## 画面遷移中の再生保持

YouTube iframeは曲詳細コンポーネント内ではなく、`App.vue`から常時マウントする`YoutubeMvPlaybackDock`で一つだけ管理する。曲詳細側の「別のMV」「MVを閉じる」はPiniaの`youtubePlayback`ストアを操作する。これにより、カテゴリをドラッグして並べ替えたり、お気に入り・検索など別画面へ移動したりしても同じiframeと再生位置を保持する。ログアウト時だけストアをリセットする。

MV取得に失敗した曲でも、BPMリズム再生は利用できる。

## データ設計

既存の曲マスタ項目を利用する。

- `playback_provider`: `youtube`
- `playback_key`: YouTube動画ID
- `playback_url`: 旧データ互換のため保持するが、YouTube MV再生では使用しない

管理者画面でYouTube動画IDを入力する必要はない。管理者の曲一覧から「詳細・MV」で曲詳細へ移動し、一般ユーザーと同じ曲ID紐づけ済みのMV再生導線を利用する。MVボタン押下時に内部APIが候補を検索し、既存の再生キャッシュがある場合だけ再利用する。検索窓や動画候補の永続保存は行わない。

## 再生設計と制約

- `https://www.youtube.com/embed/{video_id}` を公式IFrameとして表示する
- 初期状態ではプレイヤーを表示せず、ユーザーの「再生する」操作で表示する
- 標準のYouTubeプレイヤー、コントロール、動画表示を隠したり置き換えたりしない
- アプリ独自の音楽プレーヤー、再生・一時停止・シーク・音量ボタンは提供しない
- 音声だけの抽出、動画を非表示にした再生、動画ファイルの保存は行わない。バックグラウンド表示は、画面下部に常時見える公式MVドックとして行う。
- MVが未登録または再生できない場合も、BPMリズム再生は利用できる

未登録曲の自動検索を使うため、`YOUTUBE_API_KEY` が必要になる。APIキーがない場合も、BPMリズムと既存の再生キャッシュは利用できる。

```dotenv
YOUTUBE_API_KEY=
YOUTUBE_REGION=JP
YOUTUBE_MAX_RESULTS=10
```

## テスト

- `youtube-player.spec.js`: 曲詳細を開き、「再生する」ボタン押下時の曲ID紐づけ検索、`autoplay=0`の公式iframe表示、動画内標準コントロールへの統一、障害時の再検索導線を確認
- `admin-songs.spec.js`: 管理者の曲一覧から曲詳細へ移動し、同じMV再生導線を確認
- 既存の曲詳細E2E: YouTube未登録時に検索UIが表示されず、BPM再生を継続できることを確認

## 曲詳細カテゴリの並び替え

曲詳細は「リズムを確認する」「MVを再生する」「歌詞を表示する」「曲の情報」を独立カードとして表示し、カード全体をポインター操作（マウス・タッチ）で移動できる。カテゴリ固有のアイコンは各見出しの先頭に置き、各カードは閉じた状態で表示し、見出しの矢印から必要な内容だけを開く。内容は上方向から滑らかに展開し、`prefers-reduced-motion`指定時はアニメーションを抑制する。並び順は`localStorage`の`utaeru.song-detail-category-order`へ保存し、曲を変えても同じブラウザでは順序を維持する。ドラッグ用の画像アイコンは表示せず、カテゴリカード自体のドラッグ操作に統一する。歌詞プレビューの歌いだしは文字アイコンで示す。
ドラッグ中はカードの前後を判定して挿入ラインを表示し、リスト先頭・カード間・末尾のいずれにもドロップできる。表示上の操作説明は重複させない。

## Issue #26 BPMフォールバック

Deezer・GetSongBPM・Spotifyで完全一致が得られない曲は、別曲のBPMを推測して保存しない。曲詳細のリズム確認内にタップテンポを用意し、ユーザーが一定間隔で4回以上タップした値を40〜240 BPMに丸め、`localStorage`へ曲ID単位で保存する。これは公式登録BPMを上書きしない端末内の暫定値であり、外部API障害や未登録曲でも練習を継続するためのフォールバックである。

## Issue #32 リズム再生と設定メニュー

リズム再生の状態とタイマーはPiniaの`rhythmPlayback`ストアで管理するが、用途は曲詳細内の練習確認に限定する。曲詳細を離れたときは`onDeactivated`でタイマーを停止する。画面遷移後も保持するのはMVだけであり、リズム再生ドックは表示しない。

詳細画面のお気に入り・プレイリスト操作は、曲一覧と同じアイコンボタンへ統一し、ラベルは`aria-label`とツールチップだけで提供する。ヘッダーのログアウトは設定メニューへ移し、同メニューからお気に入りCSV出力と曲詳細カテゴリ順のリセットを実行できる。カテゴリのドラッグ中は透明化せず、歌詞カードの文字を読み取れる状態で強調表示する。

## Issue #33 個人BPM・タグ・MV保持

タップ計測したBPMは、公式曲マスタの値を変更せず、`my_songs.bpm`へユーザー固有値として保存する。保存にはお気に入り登録が必要で、保存値はリズム確認時に公式値より優先する。未保存の計測値は従来どおり端末の`localStorage`へ保持する。

タグは`POST /api/tags`で同名を再利用し、マイリスト編集画面から作成・選択できる。YouTubeのBPM補完は音声波形解析ではなく、検索結果のタイトル・説明に明記された`BPM`/`テンポ`表記を最後のフォールバックとして読む。YouTube Data APIは音声波形を提供しないため、明記がない場合は未登録のままとする。

## Issue #34 画面遷移とMV/BPM連動

ルート切り替えにはスライドトランジションを適用する。再生中のiframeは詳細画面では曲詳細内のホストへ、他画面では画面下部のMVなしミニプレーヤーへTeleportして同一DOMを移動する。したがって、画面遷移で再生位置をリセットしない。テンポ用のミニプレーヤーは表示しない。ミニプレーヤーから曲詳細へ戻ると、MV本体とYouTube標準コントロールを再表示できる。

YouTube候補にBPMメタデータがある場合、MV再生開始時にその値でリズムタイマーを自動開始する。候補にBPMがない場合は曲マスタのBPMを補助的に使い、それもない場合はテンポを開始しない。個人BPMのタップ計測・登録UIは曲マスタBPMが未登録の曲だけに表示する。
